# OES Method Validation Protocol (OMVP) - Statistics Division

This folder holds everything that validates the 31 statistical methods of the OES Statistics Division.

| Path | What it is |
|---|---|
| `tests/test_stat_division.py` | Software validation: registry integrity, every method on its example, regression against stored references, reproducibility, invalid input, edge cases and numerical accuracy against SciPy and statsmodels. `pytest stat-validation/tests -q` |
| `mc/` | Monte Carlo harness (`mc_lib.py`), the data-generating processes (`experiments.py`) and the runner (`run_all.py`). |
| `benchmarks/` | Scripts that compare each method with reference software (SciPy, statsmodels, scikit-learn, lifelines, pingouin, scikit-posthocs, semopy) on identical data. They print the OES value next to the reference value. |
| `results/` | `mc_<method>.json` (simulation results), `benchmark_log.txt` (raw benchmark output), `ledger.json`. |
| `docs/method_docs.py` | Authored mathematical documentation, assumptions, limitations and references of every method. |
| `LEDGER.md`, `SUMMARY.md` | Implementation ledger and validation summary (generated by `tools/make_stat_summary.py`). |

## Reproduce everything

```bash
pip install numpy pandas scipy statsmodels pytest                       # engine + tests
pip install lifelines pingouin scikit-learn semopy scikit-posthocs      # benchmarks only
python -m pytest stat-validation/tests -q
python stat-validation/mc/run_all.py --budget 45                        # all Monte Carlo experiments (hours on two cores)
python stat-validation/mc/run_all.py --ids stat_cox --reps 2000         # one method
for f in stat-validation/benchmarks/bench_*.py; do python $f; done      # benchmarks
python tools/make_stat_pages.py                                         # method pages + 16-section reports
python tools/make_stat_summary.py                                       # ledger and summary
```

The engine versions pinned to the browser runtime (Pyodide 0.27: NumPy 2.0.2, pandas 2.2.3, SciPy 1.14.1, statsmodels 0.14.4) were used for the tests and the Monte Carlo runs.

## Rules followed
* No result in a report is typed by hand: simulation tables come from `results/mc_*.json`, benchmark output from the benchmark scripts, example results from running the engine.
* Replication r of scenario s at size n is seeded by `default_rng([method_code, s, n, r])`.
* A per-cell time budget caps slow experiments; the replications actually run are stored with every result and shown in the reports.
* A method that is not fully validated says so in `LEDGER.md` and on its report.
