Power and sample-size analysis: technical validation report

Sixteen-section technical report with simulation, benchmark and real-data results generated by the project code.

Validated Compared with reference software on identical data and specifications, and checked by Monte Carlo simulation.

This report validates an established method as implemented in OES. It does not claim a new estimator. All numbers were produced by the code in stat-validation/ and tools/make_stat_pages.py; the engine version was 1.5.0.

1.Methodological introduction

Power and sample-size analysis computes the power of a planned test, the sample size required for a target power, or the smallest detectable effect.

2.Historical and theoretical background

Cohen (1988) systematised effect sizes and power tables.

3.Mathematical formulation

Two-sample t: power = 1 − F_{t'}(t_{1−α/2}; df, δ) + F_{t'}(−t_{1−α/2}; df, δ), δ = d sqrt(n1n2/(n1 + n2)), noncentral t.
One-way ANOVA: power = 1 − F_{F'}(F_{1−α}; k − 1, N − k, λ), λ = f² N.
Correlation: Fisher z, power from the normal approximation with z = atanh r sqrt(n − 3) (pwr package convention).
Two proportions: arcsine transformation with Cohen's h = 2 asin sqrt p1 − 2 asin sqrt p2; χ² goodness-of-fit with noncentrality w² N.

4.Statistical assumptions

  • The effect size and variability supplied are the truth; power is conditional on them.
  • The test's own assumptions hold (normality, equal variances).

5.Estimation algorithm

  • Noncentral distribution functions from SciPy; sample size by bracketing and Brent root finding; detectable effect by expanding bracket.

6.Computational implementation

  • Module oes/engine/oes_engine/stat_resample.py, function power_analysis, registered as stat_power in stat_registry.py.
  • Runtime dependencies: NumPy, pandas and SciPy only (the packages available in the browser Pyodide runtime); no backend.
  • Input validation: missing columns, empty data, non-numeric or constant variables, wrong number of groups, singular matrices and non-convergence return a plain-language error instead of an exception (tests in stat-validation/tests/test_stat_division.py).
  • Example run time: 0.01 s in CPython; real browser (Pyodide) timing has not been measured.

7.Monte Carlo experimental design

The analytic power returned by the engine is compared with the empirical rejection rate of the actual test in a separate NumPy simulation (20,000 replications per case) that does not use the engine's code. Code: stat-validation/mc/run_all.py (power_check).

12.Diagnostics and interpretation

  • Report the effect size assumed and where it came from; plan for a smaller effect than the pilot estimate.

Diagnostics for this method are included in the result tables above.

13.Computational limitations

  • Analytic approximations only: no simulation-based power for complex designs.
  • Post-hoc power computed from the observed effect adds no information beyond the p-value.
