Generalised linear mixed model (GLMM): technical validation report

Sixteen-section technical report with simulation, benchmark and real-data results generated by the project code.

Partially validated Matches an independent quadrature MLE and published lme4 values; no direct GLMM reference implementation was available in this environment.

This report validates an established method as implemented in OES. It does not claim a new estimator. All numbers were produced by the code in stat-validation/ and tools/make_stat_pages.py; the engine version was 1.5.0.

1.Methodological introduction

The generalised linear mixed model extends the LMM to binary and count outcomes with a random intercept for each cluster.

2.Historical and theoretical background

Breslow and Clayton (1993) popularised approximate inference; adaptive Gauss-Hermite quadrature (Liu and Pierce 1994) gives accurate marginal likelihoods for one random effect.

3.Mathematical formulation

g(μ_ij) = x_ij'β + b_i, b_i ~ N(0, σ_b²); y_ij | b_i from a binomial or Poisson family.
Marginal likelihood: L = Π_i ∫ Π_j f(y_ij | b) φ(b; 0, σ_b²) db, approximated by adaptive Gauss-Hermite quadrature with q nodes (q = 1 is the Laplace approximation).
Maximisation over (β, log σ_b) by quasi-Newton; Wald tests from the numerical Hessian; likelihood-ratio test of σ_b = 0 uses the 50:50 mixture of χ²(0) and χ²(1).

4.Statistical assumptions

  • Normally distributed random intercepts.
  • Correct link and family; independence given the random effect.

5.Estimation algorithm

  • Vectorised adaptive quadrature per cluster (mode and curvature found by Newton iterations), BFGS on the marginal log-likelihood.

6.Computational implementation

  • Module oes/engine/oes_engine/stat_mixed.py, function glmm, registered as stat_glmm in stat_registry.py.
  • Runtime dependencies: NumPy, pandas and SciPy only (the packages available in the browser Pyodide runtime); no backend.
  • Input validation: missing columns, empty data, non-numeric or constant variables, wrong number of groups, singular matrices and non-convergence return a plain-language error instead of an exception (tests in stat-validation/tests/test_stat_division.py).
  • Example run time: 0.38 s in CPython; real browser (Pyodide) timing has not been measured.

7.Monte Carlo experimental design

Each replication draws a new data set from a fixed data-generating process and runs the engine exactly as the web page does. Replication r at size n uses numpy.random.default_rng([method_code, scenario_index, n, r]), so any replication can be rerun alone. Failures are counted, never discarded silently. Sizes n are the total number of observations (subjects for repeated-measures designs, studies for meta-analysis). A per-cell time budget of 45.0 s stops very slow cells early; the replications actually run are shown in every results table.

12.Diagnostics and interpretation

  • exp(β) is a cluster-specific odds ratio (binomial) or rate ratio (Poisson); the latent intraclass correlation is σ_b²/(σ_b² + π²/3) for the logit link.

13.Computational limitations

  • Random intercepts only; no random slopes.
  • The coefficients are cluster-conditional (not population-averaged): use GEE for the latter.
  • No overdispersion model for the Poisson family; the validation is against an independent brute-force quadrature and published lme4 values, with no direct R run.

Slowest simulated cell: 1.017 s per run (Binomial random intercept, beta=0.5, sd=1, 10 per cluster, n = 1000), in CPython on a shared two-core machine. Browser speed with Pyodide is expected to be several times slower and was not measured.
