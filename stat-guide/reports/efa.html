Exploratory factor analysis (EFA): technical validation report

Sixteen-section technical report with simulation, benchmark and real-data results generated by the project code.

Validated Compared with reference software on identical data and specifications, and checked by Monte Carlo simulation.

This report validates an established method as implemented in OES. It does not claim a new estimator. All numbers were produced by the code in stat-validation/ and tools/make_stat_pages.py; the engine version was 1.5.0.

1.Methodological introduction

Exploratory factor analysis models the correlations among observed variables by a smaller number of latent common factors, estimated by maximum likelihood, and rotates the solution for interpretation.

2.Historical and theoretical background

Spearman (1904) and Thurstone; Joreskog (1967) made maximum likelihood estimation practical; Kaiser (1958) proposed varimax.

3.Mathematical formulation

x = Λ f + ε, Var(f) = I (orthogonal) or Φ, Var(ε) = Ψ diagonal; Σ = ΛΛ' + Ψ.
ML discrepancy: F(Λ, Ψ) = log|Σ| + tr(Σ⁻¹ R) − log|R| − p, minimised with respect to Ψ (Λ concentrated out by an eigen-decomposition of Ψ^{-1/2} R Ψ^{-1/2}).
Likelihood-ratio test of exact fit: χ² = (n − 1 − (2p + 5)/6 − 2m/3) F̂ with df = [(p − m)² − (p + m)]/2.
Rotations: varimax (orthogonal), promax (oblique, power 4 from the varimax solution), oblimin by gradient projection.

4.Statistical assumptions

  • Continuous (approximately multivariate normal) data for the ML estimates and the χ² test.
  • The number of factors is chosen beforehand; df ≥ 0 so the model is identified.
  • Large enough sample (a common minimum is 5–10 observations per variable).

5.Estimation algorithm

  • L-BFGS-B on the uniquenesses with bounds [0.005, 1] and analytic gradient; Heywood cases (uniqueness at the lower bound) are flagged; rotation by iterative algorithms; Kaiser-Meyer-Olkin, Bartlett sphericity and parallel analysis as diagnostics.

6.Computational implementation

  • Module oes/engine/oes_engine/stat_multivariate.py, function efa, registered as stat_efa in stat_registry.py.
  • Runtime dependencies: NumPy, pandas and SciPy only (the packages available in the browser Pyodide runtime); no backend.
  • Input validation: missing columns, empty data, non-numeric or constant variables, wrong number of groups, singular matrices and non-convergence return a plain-language error instead of an exception (tests in stat-validation/tests/test_stat_division.py).
  • Example run time: 0.14 s in CPython; real browser (Pyodide) timing has not been measured.

7.Monte Carlo experimental design

Each replication draws a new data set from a fixed data-generating process and runs the engine exactly as the web page does. Replication r at size n uses numpy.random.default_rng([method_code, scenario_index, n, r]), so any replication can be rerun alone. Failures are counted, never discarded silently. Sizes n are the total number of observations (subjects for repeated-measures designs, studies for meta-analysis). A per-cell time budget of 8.0 s stops very slow cells early; the replications actually run are shown in every results table.

12.Diagnostics and interpretation

  • Loadings show how strongly a variable reflects a factor; communality is the share of its variance explained by the common factors; the χ² test of exact fit is very demanding, so consult RMSEA as well.

13.Computational limitations

  • Heywood cases (uniqueness near 0) occur in small samples.
  • Rotated solutions are unique only up to the rotation criterion chosen.
  • Ordinal items would call for polychoric correlations, which are not implemented: Pearson correlations are used.

Slowest simulated cell: 0.044 s per run (Loading, t(5) noise (robustness), n = 1000), in CPython on a shared two-core machine. Browser speed with Pyodide is expected to be several times slower and was not measured.
