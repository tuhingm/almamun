Fine-Gray competing-risks regression: technical validation report

Sixteen-section technical report with simulation, benchmark and real-data results generated by the project code.

Partially validated Point estimates validated (equals Cox when no competing events; simulation unbiased). Standard errors omit the censoring-weight estimation variance and no R cmprsk comparison was possible, so inference rests on simulation only.

This report validates an established method as implemented in OES. It does not claim a new estimator. All numbers were produced by the code in stat-validation/ and tools/make_stat_pages.py; the engine version was 1.5.0.

1.Methodological introduction

The Fine-Gray model regresses the subdistribution hazard of one cause of failure in the presence of competing risks, so that covariate effects translate into effects on the cumulative incidence.

2.Historical and theoretical background

Fine and Gray (1999); the cumulative incidence estimator is the Aalen-Johansen estimator.

3.Mathematical formulation

Subdistribution hazard: λ_1(t | x) = λ_10(t) exp(x'β), with the risk set containing subjects who have failed from a competing cause, weighted by w_i(t) = Ĝ(t)/Ĝ(min(T_i, t)), Ĝ the Kaplan-Meier estimate of the censoring distribution.
Weighted partial likelihood with Breslow-type denominators; Newton-Raphson.
Cumulative incidence F_1(t | x) = 1 − exp{−Λ_10(t) exp(x'β)}; the Aalen-Johansen estimator gives the nonparametric benchmark.

4.Statistical assumptions

  • Independent censoring (possibly depending on covariates is not supported).
  • Proportional subdistribution hazards.
  • Event types correctly coded; one competing cause group.

5.Estimation algorithm

  • IPCW weights constructed as a matrix over event times; weighted partial likelihood maximised by Newton-Raphson; Breslow baseline.

6.Computational implementation

  • Module oes/engine/oes_engine/stat_survival.py, function fine_gray, registered as stat_finegray in stat_registry.py.
  • Runtime dependencies: NumPy, pandas and SciPy only (the packages available in the browser Pyodide runtime); no backend.
  • Input validation: missing columns, empty data, non-numeric or constant variables, wrong number of groups, singular matrices and non-convergence return a plain-language error instead of an exception (tests in stat-validation/tests/test_stat_division.py).
  • Example run time: 0.02 s in CPython; real browser (Pyodide) timing has not been measured.

7.Monte Carlo experimental design

Each replication draws a new data set from a fixed data-generating process and runs the engine exactly as the web page does. Replication r at size n uses numpy.random.default_rng([method_code, scenario_index, n, r]), so any replication can be rerun alone. Failures are counted, never discarded silently. Sizes n are the total number of observations (subjects for repeated-measures designs, studies for meta-analysis). A per-cell time budget of 8.0 s stops very slow cells early; the replications actually run are shown in every results table.

12.Diagnostics and interpretation

  • exp(β) is a subdistribution hazard ratio: it describes the effect on the cumulative incidence of the cause, not on the cause-specific hazard.

Diagnostics for this method are included in the result tables above.

13.Computational limitations

  • The standard errors treat the censoring weights as known, so they omit the variance from estimating the censoring distribution (the simulation shows the effect on coverage). This is a known simplification: the result should be called a partially validated implementation.
  • Time-varying covariates and several competing groups are not supported.

Slowest simulated cell: 0.117 s per run (Subdistribution log-HR beta=0.7 (Fine-Gray DGP), n = 1000), in CPython on a shared two-core machine. Browser speed with Pyodide is expected to be several times slower and was not measured.
