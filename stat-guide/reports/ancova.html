Analysis of covariance (ANCOVA): technical validation report

Sixteen-section technical report with simulation, benchmark and real-data results generated by the project code.

Validated Compared with reference software on identical data and specifications, and checked by Monte Carlo simulation.

This report validates an established method as implemented in OES. It does not claim a new estimator. All numbers were produced by the code in stat-validation/ and tools/make_stat_pages.py; the engine version was 1.5.0.

1.Methodological introduction

ANCOVA compares group means after adjusting for one or more continuous covariates, increasing precision and removing covariate imbalance.

2.Historical and theoretical background

Fisher introduced the analysis of covariance in the 1930s as a way to combine regression and ANOVA.

3.Mathematical formulation

Model: y_ij = μ + α_i + Σ β_k (x_kij − x̄_k) + ε_ij.
Type III F test of the group effect: F = [(SSE_reduced − SSE_full) / (k − 1)] / [SSE_full / (N − k − p)].
Adjusted mean of group i: ȳ_i − Σ β̂_k (x̄_ki − x̄_k); pairwise differences use the t distribution with the residual df and the standard error of a contrast of the fitted coefficients.

4.Statistical assumptions

  • Linear relation between covariate and outcome, with the same slope in every group (homogeneity of regression slopes; tested and reported).
  • Covariates measured without error and unaffected by the treatment.
  • Independent normal errors with constant variance.

5.Estimation algorithm

  • OLS with effect-coded groups plus covariates; hypothesis tests from nested fits; adjusted means from predictions at the covariate means; Holm-adjusted pairwise contrasts.

6.Computational implementation

  • Module oes/engine/oes_engine/stat_anova.py, function ancova, registered as stat_ancova in stat_registry.py.
  • Runtime dependencies: NumPy, pandas and SciPy only (the packages available in the browser Pyodide runtime); no backend.
  • Input validation: missing columns, empty data, non-numeric or constant variables, wrong number of groups, singular matrices and non-convergence return a plain-language error instead of an exception (tests in stat-validation/tests/test_stat_division.py).
  • Example run time: 0.01 s in CPython; real browser (Pyodide) timing has not been measured.

7.Monte Carlo experimental design

Each replication draws a new data set from a fixed data-generating process and runs the engine exactly as the web page does. Replication r at size n uses numpy.random.default_rng([method_code, scenario_index, n, r]), so any replication can be rerun alone. Failures are counted, never discarded silently. Sizes n are the total number of observations (subjects for repeated-measures designs, studies for meta-analysis). A per-cell time budget of 15.0 s stops very slow cells early; the replications actually run are shown in every results table.

12.Diagnostics and interpretation

  • The adjusted differences answer 'what would the group difference be at equal covariate values'.
  • If the slope-homogeneity test rejects, report the interaction rather than the adjusted means.

13.Computational limitations

  • A covariate that is itself affected by the grouping variable biases the adjusted difference.
  • Non-parallel slopes make a single adjusted difference misleading.

Slowest simulated cell: 0.017 s per run (Adjusted difference, t(3) errors, n = 1000), in CPython on a shared two-core machine. Browser speed with Pyodide is expected to be several times slower and was not measured.
