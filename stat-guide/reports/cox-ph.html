Cox proportional hazards model: technical validation report

Sixteen-section technical report with simulation, benchmark and real-data results generated by the project code.

Validated Compared with reference software on identical data and specifications, and checked by Monte Carlo simulation.

This report validates an established method as implemented in OES. It does not claim a new estimator. All numbers were produced by the code in stat-validation/ and tools/make_stat_pages.py; the engine version was 1.5.0.

1.Methodological introduction

The Cox proportional hazards model relates covariates to the hazard of an event without specifying the baseline hazard.

2.Historical and theoretical background

Cox (1972); Efron (1977) gave the tie approximation used by default; Grambsch and Therneau (1994) the test of proportional hazards.

3.Mathematical formulation

h(t | x) = h_0(t) exp(x'β).
Partial likelihood (Breslow ties): L(β) = Π_i [exp(x_i'β) / Σ_{j ∈ R(t_i)} exp(x_j'β)]^{δ_i}; Efron's version replaces the risk-set denominator for tied events by Σ_{R} − ((l − 1)/d) Σ_{tied}.
Newton-Raphson on the log partial likelihood with step-halving; SE = sqrt diag(I(β̂)⁻¹); Wald, score and likelihood-ratio tests.
Harrell's C; Breslow baseline cumulative hazard; scaled Schoenfeld residuals for the proportional hazards test.

4.Statistical assumptions

  • Proportional hazards (tested).
  • Non-informative censoring.
  • Log-linear effect of continuous covariates.
  • Independent subjects.

5.Estimation algorithm

  • Sorted risk sets with cumulative sums for O(n) evaluation of the gradient and information; Efron or Breslow ties; step-halving; convergence on the relative change in log-likelihood and gradient.

6.Computational implementation

  • Module oes/engine/oes_engine/stat_survival.py, function cox_ph, registered as stat_cox in stat_registry.py.
  • Runtime dependencies: NumPy, pandas and SciPy only (the packages available in the browser Pyodide runtime); no backend.
  • Input validation: missing columns, empty data, non-numeric or constant variables, wrong number of groups, singular matrices and non-convergence return a plain-language error instead of an exception (tests in stat-validation/tests/test_stat_division.py).
  • Example run time: 0.02 s in CPython; real browser (Pyodide) timing has not been measured.

7.Monte Carlo experimental design

Each replication draws a new data set from a fixed data-generating process and runs the engine exactly as the web page does. Replication r at size n uses numpy.random.default_rng([method_code, scenario_index, n, r]), so any replication can be rerun alone. Failures are counted, never discarded silently. Sizes n are the total number of observations (subjects for repeated-measures designs, studies for meta-analysis). A per-cell time budget of 8.0 s stops very slow cells early; the replications actually run are shown in every results table.

12.Diagnostics and interpretation

  • exp(β) is a hazard ratio: 1.5 means a 50% higher instantaneous event rate per unit of the covariate, at every time.
  • A significant Schoenfeld test indicates a time-varying effect.

13.Computational limitations

  • Time-varying covariates and strata are not supported.
  • Perfect separation (a covariate that predicts events exactly) makes the estimate diverge; the engine detects non-convergence and reports it.

Slowest simulated cell: 0.185 s per run (No censoring, n = 1000), in CPython on a shared two-core machine. Browser speed with Pyodide is expected to be several times slower and was not measured.
