Two-way ANOVA: technical validation report

Sixteen-section technical report with simulation, benchmark and real-data results generated by the project code.

Validated Compared with reference software on identical data and specifications, and checked by Monte Carlo simulation.

This report validates an established method as implemented in OES. It does not claim a new estimator. All numbers were produced by the code in stat-validation/ and tools/make_stat_pages.py; the engine version was 1.5.0.

1.Methodological introduction

Two-way ANOVA tests the effects of two crossed factors and their interaction on a continuous outcome, with Type II or Type III sums of squares for unbalanced data.

2.Historical and theoretical background

The factorial design and its analysis go back to Fisher's work at Rothamsted (Fisher 1925, 1935); the Type I/II/III terminology for unbalanced data was popularised by statistical packages in the 1970s.

3.Mathematical formulation

Model: y_ijk = μ + α_i + β_j + (αβ)_ij + ε_ijk, ε ~ N(0, σ²), with sum-to-zero (effect) coding.
Type III SS of a term = SS_residual(model without the term) − SS_residual(full model), each term adjusted for all others; Type II adjusts for terms that do not contain it.
F = (SS_term / df_term) / MS_residual ~ F(df_term, df_res).
Partial η² = SS_term / (SS_term + SS_res), with a confidence interval from the noncentral F distribution.

4.Statistical assumptions

  • Independent observations.
  • Normal errors with constant variance across cells (Levene/Brown-Forsythe is reported).
  • No empty cells when the interaction is included.

5.Estimation algorithm

  • Nested least-squares fits with effect-coded design matrices; term SS by differences of residual SS; estimated marginal means as unweighted means of cell means.

6.Computational implementation

  • Module oes/engine/oes_engine/stat_anova.py, function anova2, registered as stat_anova2 in stat_registry.py.
  • Runtime dependencies: NumPy, pandas and SciPy only (the packages available in the browser Pyodide runtime); no backend.
  • Input validation: missing columns, empty data, non-numeric or constant variables, wrong number of groups, singular matrices and non-convergence return a plain-language error instead of an exception (tests in stat-validation/tests/test_stat_division.py).
  • Example run time: 0.03 s in CPython; real browser (Pyodide) timing has not been measured.

7.Monte Carlo experimental design

Each replication draws a new data set from a fixed data-generating process and runs the engine exactly as the web page does. Replication r at size n uses numpy.random.default_rng([method_code, scenario_index, n, r]), so any replication can be rerun alone. Failures are counted, never discarded silently. Sizes n are the total number of observations (subjects for repeated-measures designs, studies for meta-analysis). A per-cell time budget of 45.0 s stops very slow cells early; the replications actually run are shown in every results table.

12.Diagnostics and interpretation

  • Read the interaction first: if it is significant, describe effects of one factor at each level of the other.
  • Partial η² is comparable across terms within one analysis.

13.Computational limitations

  • Main effects are hard to interpret when the interaction is large.
  • Type III results depend on the coding; the engine fixes sum-to-zero coding, which is the convention that makes Type III meaningful.

Slowest simulated cell: 0.025 s per run (Power: interaction = 0.8, n = 1000), in CPython on a shared two-core machine. Browser speed with Pyodide is expected to be several times slower and was not measured.
