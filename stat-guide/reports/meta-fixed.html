Fixed-effect meta-analysis: technical validation report

Sixteen-section technical report with simulation, benchmark and real-data results generated by the project code.

Validated, small-study tests unchecked Pooling and heterogeneity match statsmodels and metafor; Egger and Begg tests were not cross-checked.

This report validates an established method as implemented in OES. It does not claim a new estimator. All numbers were produced by the code in stat-validation/ and tools/make_stat_pages.py; the engine version was 1.5.0.

1.Methodological introduction

Fixed-effect (common-effect) meta-analysis pools study effect estimates by inverse-variance weighting under the assumption that all studies estimate one true effect.

2.Historical and theoretical background

Classical inverse-variance pooling (Hedges and Olkin 1985); Cochran's Q for heterogeneity.

3.Mathematical formulation

θ̂ = Σ w_i y_i / Σ w_i, w_i = 1/v_i; Var θ̂ = 1/Σ w_i; Wald z = θ̂/SE.
Cochran's Q = Σ w_i (y_i − θ̂)² ~ χ²(k − 1); I² = max(0, (Q − (k − 1))/Q); H² = Q/(k − 1).
Effect sizes: log risk ratio, log odds ratio and risk difference from counts (0.5 continuity correction when a cell is zero), Hedges' g from means, or supplied estimates with SE or variance.

4.Statistical assumptions

  • One true effect shared by all studies.
  • Within-study variances treated as known.
  • Independent studies.

5.Estimation algorithm

  • Effect-size computation, inverse-variance pooling, heterogeneity statistics, leave-one-out analysis, Egger and Begg small-study tests, forest plot.

6.Computational implementation

  • Module oes/engine/oes_engine/stat_meta.py, function meta_fixed, registered as stat_meta_fixed in stat_registry.py.
  • Runtime dependencies: NumPy, pandas and SciPy only (the packages available in the browser Pyodide runtime); no backend.
  • Input validation: missing columns, empty data, non-numeric or constant variables, wrong number of groups, singular matrices and non-convergence return a plain-language error instead of an exception (tests in stat-validation/tests/test_stat_division.py).
  • Example run time: 0.01 s in CPython; real browser (Pyodide) timing has not been measured.

7.Monte Carlo experimental design

Each replication draws a new data set from a fixed data-generating process and runs the engine exactly as the web page does. Replication r at size n uses numpy.random.default_rng([method_code, scenario_index, n, r]), so any replication can be rerun alone. Failures are counted, never discarded silently. Sizes n are the total number of observations (subjects for repeated-measures designs, studies for meta-analysis). A per-cell time budget of 8.0 s stops very slow cells early; the replications actually run are shown in every results table.

12.Diagnostics and interpretation

  • The pooled estimate is the weighted average effect; read Q and I² before relying on it.

Diagnostics for this method are included in the result tables above.

13.Computational limitations

  • With real between-study heterogeneity the confidence interval is too narrow (see the simulation): use the random-effects model.
  • Egger and Begg tests have low power with fewer than about 10 studies and were not cross-checked against another package.

Slowest simulated cell: 0.032 s per run (Heterogeneous tau2=0.1 (fixed-effect misspecified), n = 200), in CPython on a shared two-core machine. Browser speed with Pyodide is expected to be several times slower and was not measured.

14.Conclusions

Status: Validated, small-study tests unchecked. Pooling and heterogeneity match statsmodels and metafor; Egger and Begg tests were not cross-checked.

  • Homogeneous, theta=0.3 (fixed-effect, correct model): Power (p): n=10: 0.969, n=20: 1.000, n=50: 1.000, n=100: 1.000, n=200: 1.000.
