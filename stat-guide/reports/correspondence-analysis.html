Correspondence analysis (CA): technical validation report

Sixteen-section technical report with simulation, benchmark and real-data results generated by the project code.

Validated Compared with reference software on identical data and specifications, and checked by Monte Carlo simulation.

This report validates an established method as implemented in OES. It does not claim a new estimator. All numbers were produced by the code in stat-validation/ and tools/make_stat_pages.py; the engine version was 1.5.0.

1.Methodological introduction

Correspondence analysis represents the rows and columns of a contingency table as points in a low-dimensional space that displays the pattern of association.

2.Historical and theoretical background

Developed in the French school (Benzecri) from earlier work of Hirschfeld and Fisher; see Greenacre (1984).

3.Mathematical formulation

P = N/n, row masses r, column masses c; standardised residuals S = D_r^{-1/2}(P − rc')D_c^{-1/2}.
SVD S = U Γ V'; principal row coordinates F = D_r^{-1/2} U Γ, column coordinates G = D_c^{-1/2} V Γ.
Total inertia = Σ γ_k² = χ²/n (Pearson χ²), tested against χ²((I − 1)(J − 1)).
Contribution of a row to a dimension: r_i F_ik²/γ_k²; quality cos²_ik = F_ik²/Σ_k F_ik².

4.Statistical assumptions

  • A table of non-negative counts; independent observations for the χ² test of independence.
  • Expected counts large enough for the χ² approximation.

5.Estimation algorithm

  • SVD of the standardised residual matrix; coordinates, contributions, qualities and Cramer's V.

6.Computational implementation

  • Module oes/engine/oes_engine/stat_multivariate.py, function ca, registered as stat_ca in stat_registry.py.
  • Runtime dependencies: NumPy, pandas and SciPy only (the packages available in the browser Pyodide runtime); no backend.
  • Input validation: missing columns, empty data, non-numeric or constant variables, wrong number of groups, singular matrices and non-convergence return a plain-language error instead of an exception (tests in stat-validation/tests/test_stat_division.py).
  • Example run time: 0.00 s in CPython; real browser (Pyodide) timing has not been measured.

7.Monte Carlo experimental design

Each replication draws a new data set from a fixed data-generating process and runs the engine exactly as the web page does. Replication r at size n uses numpy.random.default_rng([method_code, scenario_index, n, r]), so any replication can be rerun alone. Failures are counted, never discarded silently. Sizes n are the total number of observations (subjects for repeated-measures designs, studies for meta-analysis). A per-cell time budget of 15.0 s stops very slow cells early; the replications actually run are shown in every results table.

13.Computational limitations

  • The χ² test needs adequate expected counts; the plot is descriptive.
  • Distances between row points and column points are not directly comparable in the symmetric map.

Slowest simulated cell: 0.003 s per run (H0 independence, chi-square test, n = 50), in CPython on a shared two-core machine. Browser speed with Pyodide is expected to be several times slower and was not measured.
