Intraclass correlation (ICC) and reliability: technical validation report

Sixteen-section technical report with simulation, benchmark and real-data results generated by the project code.

Validated Compared with reference software on identical data and specifications, and checked by Monte Carlo simulation.

This report validates an established method as implemented in OES. It does not claim a new estimator. All numbers were produced by the code in stat-validation/ and tools/make_stat_pages.py; the engine version was 1.5.0.

1.Methodological introduction

Intraclass correlation coefficients measure agreement or reliability among raters or repeated measurements, in the six forms of Shrout and Fleiss.

2.Historical and theoretical background

Shrout and Fleiss (1979); confidence intervals following McGraw and Wong (1996).

3.Mathematical formulation

ANOVA mean squares: MS_R (subjects), MS_C (raters), MS_E (error), MS_W (within subjects).
ICC(1,1) = (MS_R − MS_W)/(MS_R + (k − 1)MS_W); ICC(2,1) = (MS_R − MS_E)/(MS_R + (k − 1)MS_E + k(MS_C − MS_E)/n); ICC(3,1) = (MS_R − MS_E)/(MS_R + (k − 1)MS_E).
Average-measure forms: ICC(1,k) = (MS_R − MS_W)/MS_R; ICC(2,k) = (MS_R − MS_E)/(MS_R + (MS_C − MS_E)/n); ICC(3,k) = (MS_R − MS_E)/MS_R.
Confidence intervals by F-distribution formulas of McGraw and Wong; Cronbach's α with the Feldt interval.

4.Statistical assumptions

  • Subjects are a random sample; raters random (forms 1 and 2) or fixed (form 3).
  • Normal errors; complete data (subjects with a missing rating are dropped).

5.Estimation algorithm

  • Two-way ANOVA decomposition; closed-form coefficients and intervals; F test of ICC > 0.

6.Computational implementation

  • Module oes/engine/oes_engine/stat_mixed.py, function icc, registered as stat_icc in stat_registry.py.
  • Runtime dependencies: NumPy, pandas and SciPy only (the packages available in the browser Pyodide runtime); no backend.
  • Input validation: missing columns, empty data, non-numeric or constant variables, wrong number of groups, singular matrices and non-convergence return a plain-language error instead of an exception (tests in stat-validation/tests/test_stat_division.py).
  • Example run time: 0.01 s in CPython; real browser (Pyodide) timing has not been measured.

7.Monte Carlo experimental design

Each replication draws a new data set from a fixed data-generating process and runs the engine exactly as the web page does. Replication r at size n uses numpy.random.default_rng([method_code, scenario_index, n, r]), so any replication can be rerun alone. Failures are counted, never discarded silently. Sizes n are the total number of observations (subjects for repeated-measures designs, studies for meta-analysis). A per-cell time budget of 8.0 s stops very slow cells early; the replications actually run are shown in every results table.

12.Diagnostics and interpretation

  • Common labels: below 0.5 poor, 0.5–0.75 moderate, 0.75–0.9 good, above 0.9 excellent (Koo and Li 2016 suggest these cut-offs for the confidence limits, not the point estimate).

Diagnostics for this method are included in the result tables above.

13.Computational limitations

  • Negative estimates are possible and are reported as computed.
  • Choose the form to match the design: using a consistency form for an absolute-agreement question overstates reliability.

Slowest simulated cell: 0.004 s per run (ICC(2,1): truth 1/2.2, n = 250), in CPython on a shared two-core machine. Browser speed with Pyodide is expected to be several times slower and was not measured.
